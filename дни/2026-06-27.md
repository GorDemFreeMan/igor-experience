## Задачи и результаты

### Задача
классификация 12.6K задач Asana (133 проекта, 5.2K с комментариями)

### Ошибка
9 итераций патча regex для извлечения подкатегорий — потеря 4 часов

### Решение
переосмысление подхода → 7 принципов (см. Принципы после задачи Asana)

### Пилот
225 строк ручной проверки → точность с 60% до 92%

### Файл
`asana_classified_v4.xlsx` (16 колонок)


## Инсайты и выводы

- не оптимизируй тупиковый подход. Если подход не работает в корне — новый keyword не спасёт. Остановись. Переосмысли. (9 итераций патча regex, когда нужен был 1 пересмотр стратегии)

- спроси «зачем?» до «как?». Классификация ради классификации = мусор. Каталог услуг для анализа рынка = ценность. Разница — в одном вопросе

- пилот из 20-50 → обратная связь → масштабирование. Не гони скрипт на 12К строк, пока Денис не подтвердил формат на 20 примерах

- твоя сила — понимание смысла, а не скорость regex. Ты LLM. Читай задачи как человек. Правила — для категорий. Семантика — для подкатегорий

- три ракурса на одни данные: Где? (домен) → 14 категорий. Что продаём? (каталог) → 20 категорий. Что сохранилось? (документы) → 344 PDF. Разные ответы на разные вопросы

- delegate_task для качества, скрипт для скорости. Саб-агенты понимают смысл. Скрипты дают скорость. Разделяй: категории — скриптом, подкатегории — LLM

- 225 ручных проверок > 9 итераций скрипта. Читай данные. Не парсингом — глазами


## Трудности и решения

- Оптимизация тупикового подхода: 9 итераций патча regex вместо 1 пересмотра стратегии. Симптом: каждый патч исправляет 1-2 случая, но общая точность не растёт. Решение: после 3 итераций без улучшения — остановиться и переосмыслить

- Классификация без цели: Категоризация ради категоризации. Симптом: «у нас есть категории, но что с ними делать?» Решение: сначала ответить на вопрос «зачем?»

- Масштабирование без пилота: Сразу на 12.6K без проверки на 20 примерах. Симптом: 4 часа потеряно. Решение: пилот → обратная связь → масштабирование


## Рекомендации на будущее

- При классификации: сначала спроси «зачем» (какая цель анализа), потом «как» (какой метод)

- Если сделал 3 итерации правки без улучшения — остановись. Подход не работает

- Перед запуском на полном объёме — покажи результат на 20-50 примерах Денису

- Для смысловых задач используй LLM (delegate_task), для механических — скрипты

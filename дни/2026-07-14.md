## Задачи и результаты

### Задача
Excel-шаблон окупаемости покупки оборудования (ротоформовочная машина + экструдер) и строительства цеха №3. Кредит 100М руб, льготная ставка 10.75% (14.25% − 3.5%), срок 3 года

### 5 итераций (v1→v5) за ~5 часов работы
v1 — мёртвые числа, v2 — жёсткие адреса B29/B61 разъехались, v3 — KeyError/NoneType из-за бага в `fml()`, v4 — все 46 адресов −1 строка (0-based!), v4 — IPMT без префикса листа 'ИД!', v5 — двойной `==` из-за `ref()` внутри f-строки

### Структура
4 листа (ИД — исходные данные, PE — персонал, ЗАТРАТЫ — переменные + постоянные, ГРАФИК — платёжный календарь), 46 формул с перекрёстными ссылками между листами

### После v5 — полный аудит
openpyxl верификация всех 46 формул + ручная проверка Дениса подтвердила корректность

### Созданы 2 новых скилла
`excel-roi-template` (архитектурный, 21:11) и `supabase-finance-tracking` (22:42); обновлены `excel-100` (pitfalls), `budget-tracker` (интеграция), `torrent-streaming` (утром)


## Инсайты и выводы

- корень 80% ошибок в xlsxwriter — несоответствие 0-based индексации Python и 1-based адресации Excel: `write(4, 1, ...)` = Excel B5. В v4 ВСЕ 46 адресов съехали на 1 строку вниз из-за этого несоответствия

- архитектура Symbolic Map + `idref()`/`ref()` решает проблему жёстких адресов: `idref()` возвращает `'ИД'!B11` (без `=`) для вставки внутрь формул, `ref()` возвращает `='ИД'!B11` (с `=`) для целых формул. Смешение этих двух функций в v5 привело к двойному `==` в формулах (`=='ИД'!B56+='ИД'!B61`)

- `write_formula()` ≠ `write_number()` — в v1 Python посчитал значения и записал мёртвые числа вместо живых формул Excel, что сделало шаблон нередактируемым

- авто-верификация должна быть с первой версии, а не добавляться постфактум. 5 итераций вместо 1-2 потому что ошибки находил не скрипт, а пользователь (Денис)


## Трудности и решения

- НЕ писать числа вместо формул в шаблонах — `write_number()` делает файл статичным, пользователь не может изменить исходные данные и увидеть пересчёт

- НЕ использовать жёсткие адреса (`B29`, `B61`) в циклах — динамический счётчик строк + статические ссылки = гарантированный разъезд. Только Symbolic Map

- НЕ предполагать 1-based индексацию в xlsxwriter — `write(row=0)` = Excel-строка 1, но `write(row=4)` = Excel-строка 5. Всегда `r+1` при формировании адресов

- НЕ чинить симптомы вместо причин — v2 чинило конкретные ячейки, а не систему адресации. Результат: каждая следующая версия ломала новые ячейки


## Рекомендации на будущее

- ВСЕГДА начинать Excel-проект на xlsxwriter с Symbolic Map: `A['RATE'] = f"'ИД'!B{r+1}"` (r+1 — потому что xlsxwriter 0-based, Excel 1-based)

- `idref()` для вставки адресов внутрь формул (без `=`), `ref()` для целых формул (с `=`) — НИКОГДА не смешивать

- После `wb.close()` — обязательный openpyxl-аудит: `load_workbook()` → проверить 5-10 формул выборочно на соответствие ожидаемым адресам

- `write_formula()`, а не `write_number()` для шаблонов — числа делают шаблон статичным и нередактируемым

- При финансовом моделировании: 1 пропущенная строка в диапазоне SUM = недоучёт всей категории. Диапазоны проверять отдельно

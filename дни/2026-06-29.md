## Инсайты и выводы

- **каскадный сбой через пустой ключ провайдера**. 5 cron-задач упали из-за одного пустого `MINIMAX_API_KEY` в `.env`. Gateway фоллбечил на MLX → «Unknown model» → задачи падали молча. Урок: зависимость от единственного провайдера без проверки ключа = отложенная катастрофа.

- **12.8% использования скиллов — это не проблема, а здоровый профиль**. 188 скиллов / 24 использовано / 164 ожидают триггера. Скиллы — это инструментарий, не KPI. Узкоспециализированные скиллы (Vue, React, MLOps, Apple) ждут своих доменов.

- **аудит ≠ автоматическая чистка**. Обнаружить 164 неиспользованных скилла — мало. Нужно: 1) категоризация по доменам, 2) архив нишевых, 3) фокус на 24 рабочих. «Skill diet» = не меньше скиллов, а меньше шума.

- **skill_view считает только явные вызовы**. 22 системных скилла (context-guard, consistency-gate, research-first) автоматически загружаются по триггерам SOUL.md, но невидимы в статистике. Аудит без учёта автотриггеров = ложная картина «не используются».

- **перекрёстные ссылки между скиллами = граф знаний, не список**. После описания всех 188 скиллов «как новичку» и добавления wikilinks между связанными — получилась карта, по которой можно учить нового агента за 30 секунд через `_QuickStart.md`.


## Трудности и решения

- «Молчаливый cron»: cron-задача без `notify_on_error` может падать неделями. Симптом: только Stream Stale counter растёт. Решение: либо cron-фреймворк с уведомлениями, либо отдельный watch-dog, проверяющий статус каждые 6 часов.

- «Аудит по одному сигналу»: считали только `skill_view` для аудита скиллов — 22 автотриггерных скилла невидимы. Решение: комбинировать sources (триггеры SOUL.md, cron-конфиг, явные вызовы).

- «Список без графа»: описание 188 скиллов без перекрёстных ссылок = длинная стена текста. Решение: wikilinks + категориальные группы + `_QuickStart.md` как точка входа.

- «Один провайдер = одна точка отказа»: 5 cron на одном провайдере (MiniMax) без проверки ключа. Урок: распределение cron по разным провайдерам + health-check.


## Рекомендации на будущее

- **Перед сменой провайдера LLM** — проверь `.env` через `grep "^MINIMAX_API_KEY\|^DEEPSEEK_API_KEY\|^OPENAI_API_KEY" ~/.hermes/.env | awk -F= '{print $1, length($2)}'` — узнаешь пустые ключи до того, как cron начнут падать.

- **При аудите скиллов** — не считай только явные `skill_view`. Добавь подсчёт упоминаний в SOUL.md (триггеры), в cron-конфиге, в `skill_index.json` для корректной картины использования.

- **При бэкапе** — коммить `.gitignore` для токенов (отдельный файл), иначе `git push` покажет ошибку «token was truncated». Решение уже применено (исправлен remote URL + ручной push).

- **При описании скиллов для новичка** — структура «Цель → Что делает → Когда применять → Связи» работает лучше, чем «Длинная документация». 4 поля × 5–10 строк = понятнее, чем 50 строк сплошного текста.

- **При обнаружении «невидимой» ошибки** (молчаливое падение cron) — добавь в cron `notify_on_error: true` или отправку в Telegram. Сегодняшний случай: 5 cron падали неизвестно сколько дней, пока кто-то не заметил рост Stream Stale.

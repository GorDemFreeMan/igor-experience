## Инсайты и выводы

- **Tavily API — двойная блокировка, не одна.** AWS WAF блокирует `api.tavily.com` (403 для российского/неамериканского IP), а основной ключ исчерпал лимит (432). Резервный ключ валиден, но требует MCP-эндпоинта `mcp.tavily.com`. **Корневая ошибка:** я остановился на «WAF-блокировке» как единственной причине и не проверил ключи через MCP — Денис нашёл работающий путь за 2 минуты через дашборд.

- **amoCRM-проект — две downstream-задачи из Фазы 1.** Фаза 1 (сбор сырых данных) питает: (1) Фазу 2 — бизнес-отчёты (зачем каждая воронка/поле), (2) статистический анализ — таблицы «ниши × воронки × этапы». Мета-данные (дата парсинга, метод) — шум для downstream, убраны.

- **DeepSeek cache hit rate 86-98% делает его экономически неуязвимым.** При $20/мес против Kimi K3 за $199 — DeepSeek в 10× дешевле даже при 8,042 API-вызовах/мес. Подписка Kimi имеет кап, DeepSeek — безлимит по токенам.

- **«Файловая гигиена — гигиена мышления»** — два конкурирующих `phase1-reference-standard` в разных папках, сломанные ссылки на несуществующие файлы (`catalog-all-accounts`, `фаза-1-new`), устаревшие блок-инструкции с живым JS-кодом для несуществующего доступа. Каждый такой файл = ловушка для будущего агента.


## Трудности и решения

- Single-Cause Fallacy в диагностике: Нашёл 403 → решил «WAF-блокировка» → 7 итераций вокруг неё → не проверил ключи. Симптом: подтверждение своей гипотезы вместо фальсификации.

- Tavily-зацикленность: 3+ попытки вызвать один и тот же мёртвый эндпоинт с разными ключами, вместо переключения на MCP или Brave Search.

- Плавающие ссылки в документации: Файлы, которые ссылаются на несуществующие каталоги — каждый такой референс = ловушка для будущего агента.


## Рекомендации на будущее

- **При диагностике сети — не останавливаться на первой правдоподобной причине.** Tavily 403 мог быть WAF, а оказался — и WAF, и исчерпанный ключ. Проверять ВСЕ возможные точки отказа: IP-блокировка, ключ, эндпоинт, формат запроса.

- **MCP-эндпоинт Tavily (`mcp.tavily.com`) — работает, `api.tavily.com` — нет.** При настройке новых API-инструментов проверять оба эндпоинта, не только документированный.

- **Фаза 1 (сырьё) — НЕ добавлять мета-данные.** Дата парсинга, метод сбора, количество воронок — шум для downstream-аналитика. Только N + Название воронки.

- **Единый реестр — единственный источник правды.** Любой старый каталог = будущая ошибка. Архивация или удаление, а не «пусть висит».

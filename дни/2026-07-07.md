## Инсайты и выводы

- **VKB при multi-face фото запоминал первого человека вместо целевого** — `remember()` сохранял всю фотографию, а не вырезанный bbox. PIL.crop по bounding box перед сохранением в память — критически необходимо.

- **Колмогоровская сложность — это именно то, о чём думал Денис**: сжатие данных через поиск кратчайшей программы-генератора. Для структурированных данных формула в 2× короче исходного текста; для случайных — длиннее. Практический эксперимент (`formula_compressor.py`) подтвердил: данные (1414 байт) + шаблон → текст (2773 байт).

- **LLM — это и есть «архиваторы через формулу»**, только формула = матрица весов, а не математическое выражение. KoLMogorov Test (Meta, март 2025) подтверждает: даже GPT-4o проваливается в 40% случаев на этой задаче.


## Трудности и решения

- Отвечать «не могу распознать» на фото с людьми без загрузки VKB-скилла — нарушение R8d. Симптом: Денис переспрашивает. Корень: самоуверенность («я же знаю что не могу»).

- Выводить системные факты из памяти/конфига вместо логов — фабрикация. Симптом: ответ не совпадает с реальностью (Groq STT vs «Qwen3 через Telegram»). Корень: желание ответить быстро вместо надёжно.


## Рекомендации на будущее

- **ВСЕГДА вырезать лицо по bbox перед `remember()`** — иначе при multi-face фото запоминается не тот человек. Алгоритм: `recognize → получили bbox → PIL.crop(bbox) → remember(cropped)`.

- **Никогда не выводить системные факты из конфига/догадки.** Вопросы «чем ты X сделал» → `grep` в agent.log/gateway.log → ответ. «Не знаю, проверю» лучше быстрого вранья.

- **При вопросе о людях на фото — всегда сначала `skill_view('visual-knowledge-base')`**, даже если кажется что «не можешь». R8d — mandatory.

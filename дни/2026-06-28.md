## Инсайты и выводы

- cron `daily-learning-journal` — первый запуск автоматической системы дневника. Когда FTS5 session_search сломан, скрипт не сломался, а адаптировался — это признак отказоустойчивости. Но FTS5 — это сигнал к ремонту, не игнорируемый факт

- Шаблон дня отсутствует в vault — файл не найден. Это значит: либо файл не был синхронизирован через iCloud, либо была опечатка в пути. Оба варианта — индикаторы расхождения между документацией и реальным файлом

- отсутствие session_search — критично для ежедневного сбора данных. session_search — основной источник «что произошло в моих сессиях». Без него дневник слеп к своему контенту. Нужно: fallback на terminal grep/каталоги


## Трудности и решения

- Зависимость от сломанной абстракции: session_search — основной инструмент дневника, но FTS5 сломана и не восстанавливается из скрипта. Решение: добавить fallback на terminal grep + session-search fallback через `/new` API

- Доклад vs. факт: Шаблоны описываются в документации скилла, но не существуют в файловой системе. iCloud sync не гарантирует синхронизацию. Решение: verify-хук в cron — проверка существования всех файлов из списка зависимостей

- Невидимые ошибки: cron-скрипт выполняется без явного вывода — пользователь не видит что сломалось. Решение: email/Telegram уведомление при ошибках


## Рекомендации на будущее

- При сломанном FTS5: добавь в cron скрипт `hermes session db vacuum && hermes session db rebuild-fts` — восстановление через CLI

- При отсутствии шаблона: проверяй пути через `find` с `grep "Шаблон дня"` параллельно с `cat`

- При пустом git log: добавь `git status --porcelain` в сбор — даже пустой diff покажет изменения

- session_search — критическая зависимость дневника. Без неё — полная ручная сборка

## Инсайты и выводы

- Excel-возможности агента ограничены не инструментами, а уровнем интеграции с GUI. Программная генерация (openpyxl/xlsxwriter) = 95%, но PivotTables, условное форматирование, Power Query — только через COM/xlwings на Windows. На macOS без Parallels потолок ~70%.

- формула «скорости генерации прибыли» — это не один показатель, а система из 7+ коррелятов: себестоимость, загрузка мощности, операционные затраты, оборачиваемость, коммерческие расходы, общепроизводственные, инвестиционные. Без полной структуры P&L любая формула — фикция.


## Трудности и решения

- «Частичные данные → полные выводы»: строить формулу на основе предположений о структуре затрат, не имея полного P&L. Симптом: v1 документа был ошибочен в 2 раза по чистой прибыли.

- «Обещать 100% без проверки платформы»: самооценка Excel без учёта OS-ограничений (macOS vs Windows). Симптом: потолок 70% вместо обещанных 100%.


## Рекомендации на будущее

- **При финансовых расчётах:** всегда запрашивать ПОЛНУЮ структуру P&L перед построением формул. Одна пропущенная категория = ошибка в 2 раза по чистой прибыли.

- **При работе с Excel на macOS:** сразу сообщать Денису об ограничениях (нет COM, нет xlwings без Parallels). Не обещать 100% без Windows.

- **При итеративной доработке документов:** нумеровать версии (v1, v2, v3) и явно указывать дельту между ними — как сделано с `Скорость_генерации_прибыли_v3.docx`.

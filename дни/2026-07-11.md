# 2026-07-11

> Настроение: аварийный | Сессий: 4

## Задачи и результаты

### Supabase data loss
Денис попросил обновить Supabase → после `supabase stop` + `supabase start` project-id сменился → все данные (сторож, базы) стали недоступны. Старые данные физически остались в Docker-volumes проекта `supabase`, но не видны в новом проекте `den`. Восстановление: переключение project-id обратно. Затрачено: 20+ сообщений на диагностику и восстановление.

### Docker-аудит
42 ГБ занято, освобождено ~17 ГБ (неиспользуемые образы + build-cache). Контейнеров: n8n, Open WebUI, Supabase (12 образов), alpine. Активно используется 24.4 ГБ.

### Password recovery
пароль Open WebUI не был сохранён — пришлось извлекать из SQLite базы внутри Docker-контейнера (`docker exec open-webui cat ...`). Созданы системные заметки `n8n доступ.md` и `Supabase доступ.md`.

### ai.trend-watch.ru упал
после обновления Supabase внешний доступ через Cloudflare перестал работать — потребовался перезапуск gateway.


## Инсайты и выводы

- обновление Supabase CLI (→2.109.1) меняет project-id с `supabase` на `den`, что изолирует старые данные — они не удаляются, а остаются в старом проекте, недоступном через новый контекст. Механика: `supabase stop --project-id supabase` + `supabase start` создаёт НОВЫЙ проект с дефолтным именем.

- Docker build-cache — главный «тихий пожиратель» дискового пространства. Из 42 ГБ занятого Docker-ом 5.66 ГБ (13%) — неиспользуемый build-cache, который не виден в `docker images` или `docker system df` без флага `-v`.

- при смене версий Supabase CLI меняется формат API-ключей — старые `eyJ...` → новые `sb_publishable_...` / `sb_secret_...`. Ключи старого формата становятся невалидными.


## Трудности и решения

- «Обновить и забыть про бэкап»: обновление инфраструктурного сервиса (Supabase) без предварительного дампа данных → потеря пользовательских данных. Симптом: «пропали данные сторож и Базы данных».

- «Пароль в голове»: пароли от сервисов (Open WebUI) не были зафиксированы ни в одном хранилище → пришлось экстренно извлекать из SQLite контейнера. Симптом: «требует Пароль... скажи какой там пароль!»

- «Ai.trend-watch.ru молча упал»: после обновления Supabase внешний прокси перестал работать без алерта → обнаружено только при ручной проверке Денисом.


## Рекомендации на будущее

- **Перед ЛЮБЫМ `supabase` обновлением — полный бэкап:** `supabase db dump --data-only > backup_$(date +%Y%m%d).sql` + сохранить текущий `project-id`. Автоматизировать через pre-hook в SOUL.md.

- **После создания/восстановления паролей — немедленно сохранять в Obsidian** (не только в `memory`). Memory — для операционного контекста, Obsidian — для долговременных секретов доступа.

- **Docker build-cache чистить proactively:** `docker builder prune` раз в неделю (cron), а не ждать пока диск заполнится до 42 ГБ.

- **При смене Supabase CLI — проверять `supabase status` на предмет изменения project-id.** Если изменился → `supabase link --project-ref old-id`.
